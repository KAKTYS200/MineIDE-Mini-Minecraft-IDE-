# Mine IDE

**Mine IDE** — современное десктопное приложение для разработки модов Minecraft на **C# / .NET 8 / WPF**.
Интерфейс вдохновлён **Visual Studio Code**: тёмная тема по умолчанию, меню в стиле VS Code, плавные анимации,
перетаскиваемые панели, встроенный редактор кода и 3D-редактор моделей (Blockbench).

## Возможности

| Область | Что умеет |
|---|---|
| **Интерфейс** | Меню Файл/Вид/Импорт (VS Code), тулбар с проектом, сборкой и запуском, левая панель (5 вкладок), нижний терминал (6 вкладок), статус-бар, тёмная и светлая темы |
| **Панели** | Все панели растягиваются перетаскиванием за край (левая, правая, терминал, внутренние сплиттеры); правый док — на всю высоту окна |
| **Редактор кода** | Ввод, курсор, выделение, undo/redo, сохранение Ctrl+S; подсветка Java/Groovy/JSON/INI; нумерация строк; миникарта с маркером позиции |
| **Рецепты** | Визуальный редактор JSON-рецептов: крафт 3×3, печка, камнерез, кузнечный стол; перетаскивание предметов; свойства предмета и JSON-превью прямо под схемой |
| **Модели** | Настоящий **Blockbench** встроен (WebView2): Java Block/Item, Java Entity, Bedrock, Generic; тема синхронизируется с приложением; скин-формат убран |
| **Быстрый доступ** | Вкладки «Предметы» (все id из клиента Minecraft с иконками, клик — копировать id), «Изображения» и «Модели» из проекта |
| **Explorer** | Дерево файлов проекта, двойной клик — открыть; кнопка **«+»** с меню «Создать мод / Создать датапак» (готовый скаффолд по имени) |
| **Mods** | Реальный список `runs/mods/*.jar`: включить/выключить (переименование в `.jar.disabled`), **удалить** файл, выбрать любую папку с модом |
| **Сборка** | Реальная сборка Gradle (`gradlew build -x test`) со стримингом вывода и разбором ошибок/предупреждений в Problems; JAR копируется в `runs/mods` (выключенные моды не перезаписываются) |
| **Запуск** | 4 уровня: установленный Forge-клиент → `gradlew runClient/runServer/runData` → `java -jar` → симуляция; выключенный в Mods мод **не загружается** в игру |
| **Логи** | Реальные логи запущенного клиента (`runs/logs/latest.log`), консоль, Gradle-вывод |
| **Crash-отчёты** | Автопарсинг `runs/crash-reports/*.txt`: описание, стек, советы — во вкладке Crash Reports |
| **Производительность** | Реальные CPU/память запущенного Java-процесса (семплинг раз в секунду) |
| **Проекты** | Список проектов в тулбаре, автоподбор версии Forge под MC, сохранение состояния |
| **Формат .mmcp** | Собственный формат файла проекта: двойной клик по `.mmcp` открывает Mine IDE с проектом (ассоциация в реестре), «Файл → Открыть/Сохранить проект (.mmcp)» |
| **Данные** | Своя папка `%APPDATA%\MineIDE` (mods / textures / models / projects) создаётся при первом запуске |
| **Окно** | Позиция не уходит за экран (автоограничение), размер/позиция/тема запоминаются |

## Требования

- **Windows 10 / 11**
- **.NET 8 SDK** — для сборки из исходников (`dotnet build`). Готовый exe работает без установки .NET, если опубликован self-contained
- **Microsoft Edge WebView2 Runtime** — для панели «Модели» (Blockbench). Обычно уже установлен в Windows 10/11
- **Java (JDK 17+)** — для реальной сборки Gradle и запуска Minecraft
- **Gradle** или **gradlew.bat** в корне проекта — для реальной сборки
- **Установленный Forge** (например «Forge 1.20.1» в `.minecraft`, Prism/MultiMC/CurseForge) — для запуска мода в реальной игре

Без Java/Gradle/Forge приложение работает в **демо-режиме** (имитация сборки и запуска) — всё равно можно изучать интерфейс, рецепты, модели и писать код.

## Установка и запуск

Из исходников:

```bash
cd MineIDE
dotnet build
dotnet run
```

Или готовыми скриптами:

```bash
# dev-запуск
MineIDE/run.bat

# self-contained publish (папка bin/Release/net8.0-windows/win-x64/publish/)
MineIDE/release.bat
```

Открыть проект: **Файл → Открыть проект…** (папка с `build.gradle`) или кнопка 📂 в Explorer.

## Быстрый старт

1. Откройте приложение — увидите демо-проект **examplemod** (Forge 47.2.0, MC 1.20.1).
2. Смените версию Minecraft в тулбаре — список версий Forge обновится автоматически.
3. В **Explorer** двойной клик по `Examplemod.java` — редактируйте код (курсор, выделение, undo/redo).
4. Нажмите **Ctrl+S** — файл сохранится, точка в заголовке вкладки исчезнет.
5. Откройте любой `.png` — справа появится предпросмотр текстуры; `.json` отформатируется в JSON Viewer.
6. Нажмите **Run** — полный пайплайн: сборка → копирование JAR в `runs/mods` → запуск (см. [Сборка и запуск](#сборка-и-запуск)).
7. Откройте **Рецепты** — соберите крафт из предметов, JSON обновится автоматически.
8. Откройте **Модели** — встроенный Blockbench сразу загрузится с моделью-кубом.

## Редактор рецептов (крафты)

Кнопка **«Рецепты»** в тулбаре (или «Вид → Редактор рецептов»). Визуальное создание JSON-рецептов для Forge:

- **Типы рецептов:** shaped / shapeless (стол 3×3), furnace-семейство (smelting/blasting/smoking/campfire — поля «Опыт» и «Время (ticks)»), stonecutting, smithing.
- **Слоты** нарисованы поверх игрового GUI; предмет в слот можно положить перетаскиванием из палитры внизу или кликом.
- **Настройки предмета** (Item id, Количество, Group, NBT) — прямо под схемой крафта.
- **JSON-превью** — под крафтом и настройками, обновляется автоматически; кнопка «Скопировать»; блок ошибок валидации.
- Кнопки Новый / Открыть / Сохранить / Сохранить как, Undo/Redo.

---

## Редактор моделей (Blockbench)

Кнопка **«Модели»** в тулбаре (или «Вид → Редактор моделей (Blockbench)»). Внутри работает **настоящий Blockbench 5.2.0** (собранный из исходников), встроенный через WebView2:

- Виртуальный хост `blockbench.local` — без локального сервера, папка `MineIDE/Blockbench/` копируется в output.
- При открытии сразу создаётся **Java Block/Item** модель-куб (стартовый экран пропущен).
- Доступны форматы: Java Block/Item, Java Entity, Bedrock, Generic (без формата «Скин»).
- **Тема Blockbench синхронизируется** с темой приложения (хук `BlockbenchSetTheme`).
- Настройки/бэкапы Blockbench хранятся в `%LOCALAPPDATA%\MineIDE\WebView2`.
- Требуется Microsoft Edge WebView2 Runtime; иначе панель покажет понятную ошибку.

## Быстрый доступ

Кнопка в правом доке (или «Вид → Быстрый доступ»). Три вкладки:

- **Предметы** — все id предметов/блоков из локального клиента Minecraft с иконками; клик — скопировать id в буфер; поиск по Enter.
- **Изображения** — все `.png/.jpg/.gif` из текущего проекта; двойной клик — открыть.
- **Модели** — все `.json` из `models/` проекта; двойной клик — открыть.

## Explorer: создание мода и датапака

В шапке Explorer кнопка **«+»** — при наведении открывается меню:

- **«Создать мод (Forge)»** — спрашивает имя, создаёт папку с **готовой структурой Forge 1.20.1**:
  ```
  <имя>/
  ├── build.gradle / settings.gradle / gradle.properties
  ├── runs/
  └── src/main/
      ├── java/com/example/<modid>/<Класс>.java   (@Mod, шина событий, логгер)
      └── resources/
          ├── META-INF/mods.toml
          ├── pack.mcmeta
          └── assets/<modid>/  (blockstates, lang, models, textures)
  ```
- **«Создать датапак»** — готовая структура **датапака 1.20.1**:
  ```
  <имя>/
  ├── pack.mcmeta
  └── data/<namespace>/
      ├── function/     (hello.mcfunction)
      ├── advancement/
      ├── recipe/
      ├── loot_table/
      └── tags/function/
  ```

Имя преобразуется автоматически: «My Test Mod» → modid `my_test_mod`, класс `MyTestMod`. Рядом с папкой создаётся файл **`.mmcp`**. Создаётся рядом с текущим проектом; если проекта нет — в `%APPDATA%\MineIDE\projects`. Новый проект сразу добавляется в список и открывается.

## Панель Mods

- Список **реальных .jar** из `runs/mods` текущего проекта (появляются после сборки).
- **Включить/Выключить** — файл переименовывается в `.jar.disabled` и обратно (стандартное соглашение Forge: такие моды не загружаются).
- **🗑 Удалить** — удаляет файл (и `.disabled`-двойника) с диска с подтверждением.
- **📁 Выбрать папку с модом** — открыть любой каталог (скачанный мод, распакованный jar) и смотреть его дерево файлов; по умолчанию открывается `%APPDATA%\MineIDE\mods`.
- Выключенный мод **не копируется** в установку Forge при запуске и не загружается в игре; старый скопированный файл при этом удаляется.

## Сборка и запуск

**Пайплайн:** Build (`gradlew build -x test` или демо) → копирование JAR из `build/libs` в `runs/mods` → Run.

Кнопки тулбара:

| Кнопка | Действие | Клавиша |
|---|---|---|
| **Build** | Сборка без запуска | Ctrl+Shift+B |
| **Run** | Сборка + запуск | F5 |
| **Stop** | Остановить Minecraft | Shift+F5 |

Профиль запуска (справа в тулбаре): `client` / `server` / `data` — определяет gradle-задачу (`runClient`/`runServer`/`runData`).

**Порядок запуска** (что найдётся первым):

1. **Установленный Forge-клиент** (`MinecraftInstallLocator` ищет в `.minecraft`, TLauncher, Prism, MultiMC, CurseForge) — собранный JAR копируется в его папку `mods` и запускается настоящая игра;
2. **Gradle-окружение** — `gradlew runClient / runServer / runData`;
3. **`java -jar`** — одиночный jar;
4. **Симуляция** — если Java/Gradle/Forge не найдены (демо-логи с пометкой).

## Логи и отчёты об ошибках

- **Logs** — реальный файл `runs/logs/latest.log` через FileSystemWatcher (стриминг без дублей); консоль запущенного клиента.
- **Crash Reports** — автоматический парсинг `runs/crash-reports/crash-reports-*.txt`: описание краша, стек-трейс, советы. Двойной клик — открыть лог.
- **Gradle** — сырой вывод сборки; **Problems** — ошибки/предупреждения, распознанные из вывода javac/gradle.

## Темы оформления

- **Dark+** (по умолчанию, как VS Code) и **Light+** — полные палитры (панели, шрифты, акценты).
- Переключение: кнопка ☀/🌓 в тулбаре или «Вид → Сменить тему».
- Меню, выпадающие списки, блоки подсвечены в палитре приложения — контраст читаемый в обеих темах.
- Тема запоминается в настройках; тема встроенного Blockbench переключается вместе с приложением.

## Формат проекта .mmcp

Собственный формат файла проекта — JSON-дескриптор:

```json
{
  "Format": "MineIDE Project",
  "Version": 1,
  "Name": "My Mod",
  "Type": "Mod",
  "Path": "C:\\Users\\...\\AppData\\Roaming\\MineIDE\\projects\\my_mod",
  "MinecraftVersion": "1.20.1",
  "ForgeVersion": "47.2.0",
  "ModId": "my_mod",
  "Description": "...",
  "Created": "2026-08-19T00:00:00"
}
```

- **Двойной клик по `.mmcp`** — Windows запускает Mine IDE и проект открывается автоматически (ассоциация регистрируется в реестре текущего пользователя при запуске, без прав администратора).
- **Командная строка:** `MineIDE.exe путь\проект.mmcp`.
- **Меню «Файл»:** «Открыть проект (.mmcp)…», «Сохранить проект (.mmcp)…» (по умолчанию — в `%APPDATA%\MineIDE\projects`).
- При создании мода/датапака `.mmcp` пишется автоматически рядом с папкой проекта.
- Если папка проекта из файла пропала — показывается предупреждение.

## Папка данных приложения

При первом запуске создаётся **`%APPDATA%\MineIDE`** (Roaming):

```
%APPDATA%\MineIDE\
├── mods\      ← сюда по умолчанию открывается «Выбрать папку с модом»
├── textures\
├── models\
└── projects\  ← новые моды/датапаки создаются здесь (если нет выбранного проекта)
```

Путь выводится в консоль при старте: «Папка данных приложения: …».

## Настройки

- Файл: **`%LOCALAPPDATA%\MineIDE\settings.json`**.
- Сохраняются: тема, размер и позиция окна, развёрнутое состояние, последний выбранный проект.
- Окно автоматически ограничивается границами экрана — «утащить» его за монитор нельзя.
- Данные WebView2 (Blockbench): `%LOCALAPPDATA%\MineIDE\WebView2`.

## Пересборка встроенного Blockbench

Если нужно обновить Blockbench из исходников (`blockbench-5.2.0-beta.1/`):

```bash
cd blockbench-5.2.0-beta.1
npm install
npm run build-web
cp dist/bundle.js ../MineIDE/Blockbench/dist/bundle.js
```

**Важно — две кастомизации бандла, которые нужно сохранить после пересборки:**

1. **Удалить скин-формат** (иначе вернётся вкладка «Скины»): в `js/main.ts` убрать строку `import "./formats/minecraft/skin"`.
2. **Хук темы** (иначе Blockbench не будет переключаться вместе с приложением): в `js/interface/themes.ts` добавлен `window.BlockbenchSetTheme = id => …` (вызывает `theme.load()` для `default` / `default_light`).

## Реальная работа vs демо-режим

| Что | Реально | Демо (fallback) |
|---|---|---|
| Сборка | `gradlew.bat`/Gradle → `build -x test`, вывод в Build/Gradle, `error:`/`warning:` → Problems | Имитация шагов, если Gradle/Java нет |
| Копирование JAR | Из `build/libs` в `runs/mods` (выключенные моды не перезаписываются) | — |
| Запуск | Forge-клиент (jar в его mods) → `gradlew runClient/…` → `java -jar` | Имитация логов |
| Логи | Консоль `runClient` + `runs/logs/latest.log` | Фейковые строки с пометкой «демо» |
| Crash-отчёты | Парсинг `runs/crash-reports/*.txt` | Генерация из пойманных ошибок |
| Метрики | CPU/память Java-процесса | — |
| Предметы (Быстрый доступ) | id и иконки из локального клиента Minecraft | Пусто, если клиент не найден |

Откройте настоящий Forge-проект («Файл → Открыть проект…», папка с `build.gradle`) — пайплайн станет полностью реальным. Первый `runClient` может занять время: Gradle скачает зависимости.

## Устранение неполадок

| Проблема | Решение |
|---|---|
| Панель «Модели» не открывается / ошибка WebView2 | Установите **Microsoft Edge WebView2 Runtime** (бесплатно от Microsoft) |
| Сборка «симулируется» | Установите JDK 17+ и Gradle, либо положите `gradlew.bat` в корень проекта |
| Run запускает симуляцию | Установите Forge нужной версии (в `.minecraft`, TLauncher, Prism, MultiMC, CurseForge) |
| Мод не появляется в Mods | Сначала соберите проект — JAR копируется в `runs/mods` после Build |
| Мод «не выключается» | Проверьте, что в `runs/mods` нет двух файлов: `mod.jar` и `mod.jar.disabled` (сборка не перезаписывает выключенный мод) |
| Окно «пропало» за экраном | Приложение само ограничивает позицию экраном при запуске и перетаскивании |
| `.mmcp` не открывается двойным кликом | Ассоциация регистрируется при запуске приложения; убедитесь, что путь к exe не изменился после пересборки |
| Логи/краши пустые | Запустите через Run хотя бы раз — папки `runs/logs`, `runs/crash-reports` появляются после запуска игры |
